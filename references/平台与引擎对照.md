# 平台与引擎对照

## 总表

| 平台 | 引擎 | 登录凭据 | 主页批量 | 单条 | 支持的链接形态 |
| --- | --- | --- | --- | --- | --- |
| 小红书 | XHS-Downloader + 本地 MCP 服务 | `engines/xiaohongshu-mcp/cookies.json`（扫码） | ✅ | ✅ | `/explore/<id>`、`/user/profile/<id>` |
| 抖音 | MediaCrawler（自带 3.11 运行时） | 扫码登录态（本地缓存） | ✅ | ✅ | `/user/<sec_uid>`、`/video/<id>`、`/note/<id>`、`v.douyin.com` 短链、纯数字 ID |
| 推特 X | gallery-dl | `cookies/twitter/cookies.txt` | ✅ | ✅ | `x.com/<用户>`、`/status/<id>` |
| Instagram | gallery-dl | `cookies/instagram/cookies.txt` | ✅ | ✅ | `instagram.com/<用户>`、`/p/`、`/reel/` |
| TikTok | 自建 `tiktok_dl.py` | `cookies/tiktok/cookies.txt` | ✅ | ✅ | `tiktok.com/@<用户>`、`/video/<id>`、`/photo/<id>` |
| 微博 | gallery-dl | `cookies/weibo/cookies.txt`（`SUB`/`SUBP`） | ✅ | ✅ | `weibo.com/u/<uid>`、`/n/<昵称>`、`/detail/<id>` |

**所有引擎都随技能包自带**，用户电脑上不需要装 Python、pip、uv、gallery-dl、yt-dlp：

| 引擎 | 在包里的位置 |
| --- | --- |
| gallery-dl / yt-dlp | `runtime/pkgs/gallerydl/`（用 `runtime/python` 以 `-m` 方式调用） |
| XHS-Downloader | `engines/xhs-downloader/` + `runtime/pkgs/xhs/` |
| xiaohongshu-mcp | `engines/xiaohongshu-mcp/`（自带 exe） |
| TikTok 下载器 | `engines/tiktok/tiktok_dl.py` |
| MediaCrawler（抖音） | `engines/mediacrawler/` + `runtime/python311/` + `runtime/pkgs/mediacrawler/`（**可选补充包**） |

## 为什么不同平台用不同引擎

- **推特 / Instagram / 微博**：gallery-dl 对这三个站的支持最成熟，配置、命名模板、限速都能通过 `config.json` 控制，所以统一走它。
- **TikTok**：本机出口常是机房 IP，TikTok 的 CDN（Akamai）会直接对普通请求返回 403。必须用 `yt-dlp --impersonate chrome` 模拟浏览器指纹抓视频、用 `curl_cffi` 抓图文，所以单独写了一个下载器。
- **抖音**：作品清单和媒体地址需要登录态 + 签名参数，MediaCrawler 已经把这套都做好了，直接复用。它需要一个真实浏览器来执行签名脚本（`a_bogus`），所以**不打包浏览器内核**，改用用户本机已装的 Chrome / Edge（`MC_BROWSER_PATH` 环境变量注入）；都没有时引导双击 `app/安装浏览器.bat`。
- **小红书**：同样需要登录态，XHS-Downloader 负责下载，本地 MCP 服务负责「枚举某作者的全部作品」。

> 抖音的 MediaCrawler 依赖是 Python 3.11 编译的，跟主运行时的 3.12 不通用，
> 所以补充包里额外带了一份 3.11 运行时，而不是让用户去装 uv。
> 浏览器内核（Playwright Chromium，约 400MB）不再打包，用系统浏览器替代。
> 签名脚本要的 JS 运行时也不用用户装 Node —— 用 Playwright 驱动自带的 `node.exe`。

## 统一的两个约定

### 1. 先落暂存，再归位

所有下载器都先把文件写进 `运行记录/暂存/<任务ID>/`，下载完再由程序搬到用户选定的保存目录。
好处：下载器中途失败不会在保存目录留下半成品。

### 2. 两种模式的落盘方式

| 模式 | 落盘位置 |
| --- | --- |
| 下载整个主页 | `<保存目录>/<博主名>/`（各平台自动取博主昵称做目录名） |
| 只下载这一条 | 文件**直接摊在** `<保存目录>/` 根下，重名自动加 `__1` 后缀 |

## 数量上限

界面上「数量上限」留空或填 0 表示不限制。填了数字时各平台的处理方式：

| 平台 | 实现方式 |
| --- | --- |
| Instagram | `-o extractor.instagram.max-posts=N` |
| 推特 X | `-o extractor.twitter.max-posts=N` |
| 微博 | `--range 1-N`（微博提取器没有 max-posts 选项） |
| TikTok | 传给下载器的 `--limit` |
| 小红书 | 传给 `xhs_worker.py` 的 `--limit` |
| 抖音 | `--crawler_max_notes_count`，默认 50（**单条模式忽略此值**） |

## config.json 字段说明

```jsonc
{
  "port": 8790,                 // 本地服务端口
  "output_dir": "下载",          // 默认保存位置（相对 skill 目录）
  "open_browser": true,         // 启动时是否自动打开浏览器
  "chrome_path": "",            // 本机 Chrome/Edge 路径；抖音也用它（不打包浏览器内核）
  "runtime": {
    "python": "",               // 自带便携 Python 路径（runtime/python/python.exe）
    "bundled": true             // true = 用自带运行时，不依赖本机装过任何引擎
  },
  "engines": {
    "gallery_dl": "",           // 自带模式下留空，用 `python -m gallery_dl` 调用
    "yt_dlp": "",               // 同上
    "uv": "",                   // 仅「本机回退模式」跑 MediaCrawler 时才需要
    "xhs_python": "",           // 自带模式下 = runtime/python/python.exe
    "tiktok_dl": "",            // engines/tiktok/tiktok_dl.py
    "tiktok_python": ""         // 自带模式下 = runtime/python/python.exe
  },
  "platforms": {
    "twitter":   { "cookie": "", "config": "", "workdir": "" },
    "instagram": { "cookie": "", "config": "", "workdir": "" },
    "weibo":     { "cookie": "", "config": "", "workdir": "" },
    "tiktok":    { "cookie": "", "workdir": "" },
    "douyin":    { "workdir": "" },   // 装了抖音补充包才非空
    "xhs":       { "cookie": "", "workdir": "", "mcp": "http://localhost:18060" }
  }
}
```

这些值全部由 `app/配置向导.py` 自动填写，一般不需要手改。
`runtime.bundled` 为 `true` 时，向导**不会扫描本机**；只有自带件缺失才会回退扫描。
